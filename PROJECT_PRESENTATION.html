📋 Proje Özeti

Proje Tanımı

Gallery, modern web teknolojileri kullanarak geliştirilmiş, tam işlevsel bir araç galerisi yönetim sistemidir. Müşterilerin araçları listeleyebileceği, favorilere ekleyebileceği, satıcılarla mesajlaşabileceği ve araç hakkında sorular sorabileceği kullanıcı dostu bir platformdur.

Temel Amaçlar

  • Araç Listesi Yönetimi: Kullanıcıların araçları kolay bir şekilde listeleyip yönetmesi
  • Müşteri İşlemleri: Müşterilerin araçları arayabileceği ve favorilere ekleyebileceği sistem
  • Gerçek Zamanlı İletişim: Satıcı ve alıcı arasında sohbet özelliği
  • Esneklik: Filtreleme, arama ve gelişmiş sorgu seçenekleri
  • Güvenlik: Rol tabanlı erişim kontrolü ve veri koruması

💾 Veritabanı Modeli - Detaylı Yapı

📋 7 Ana Entity Tablosu

🔑 users (8 Alan)
user_id (PK) | full_name (VARCHAR 120) | email (VARCHAR 180, UNIQUE) |
password_hash (VARCHAR 255) | role (USER/ADMIN) | created_at | last_login_at (NULL) | is_active (0/1)
🚗 cars (14 Alan - images JSON içerir)
car_id (PK) | brand, model, year | price (NUMERIC 12,2) | mileage |
fuel_type, gear_type, color | description (TEXT) | images (JSON - resim listesi) |
status (AVAILABLE/SOLD) | created_by (FK users) | created_at, updated_at | sold_at (NULL) | is_deleted (0/1)
❤️ favorites (3 Alan - Composite PK)
user_id (FK users, PK) ◆ car_id (FK cars, PK) ◆ created_at (TIMESTAMP)
Özel: Bileşik anahtar (user_id, car_id) - CASCADE DELETE
❓ inquiries (8 Alan)
inquiry_id (PK) | user_id (FK users - soru soran) | car_id (FK cars) |
message (TEXT) | status (NEW/IN_PROGRESS/CLOSED) | created_at |
handled_by (FK users, NULL - admin cevaplar) | handled_at (NULL)
💬 chat_conversations (7 Alan)
conversation_id (PK) | user_id (FK users - ON DELETE CASCADE) | car_id (FK cars - ON DELETE CASCADE) |
status (OPEN/CLOSED) | created_at | updated_at | last_message_at (DESC INDEX)
Özel: UNIQUE(user_id, car_id) - Her araç-kullanıcı çifti sadece 1 konuşma
✉️ chat_messages (7 Alan)
message_id (PK) | conversation_id (FK chat_conversations - ON DELETE CASCADE) |
sender_id (FK users - ON DELETE CASCADE) | sender_role (USER/ADMIN) |
message_text (TEXT) | is_read (0/1) | created_at
📝 user_activity_logs (5 Alan) - YENİ!
log_id (PK) | user_id (FK users, NULL - başarısız girişler) | action (LOGIN/LOGOUT/FAILED_LOGIN/ACTION) |
details (JSON) | created_at (TIMESTAMP)
Amaç: Kullanıcı giriş/çıkış aktivitelerini ve güvenlik olaylarını takip etmek

🔧 Veritabanı Özellikleri

  • ✅ Foreign Key İlişkileri: Veri bütünlüğü sağlanır
  • ✅ ON DELETE CASCADE: Silinmiş kayıtlar otomatik kısıtlandırılır
  • ✅ TIMESTAMP: Otomatik zaman damgaları DEFAULT CURRENT_TIMESTAMP
  • ✅ Soft Delete: cars.is_deleted alanı
  • ✅ BIGSERIAL: Büyük ID'ler için (1-9 milyar+)
  • ✅ UNIQUE Constraints: Email benzersiz, chat UNIQUE(user_id, car_id)
  • ✅ CHECK Constraints: Geçerli enum değerleri kontrol (role, status vb.)
  • ✅ Index Optimizasyonu: Hızlı sorgulamalar için

📊 Entity Detaylı Açıklamalar

🔑 users (Merkez Entity)
Sistemin tüm kullanıcıları. Rol: USER (müşteri) veya ADMIN (satıcı). Tüm diğer entity'lere referans noktası.
🚗 cars
Araç listeleri. images alanı JSON formatında resim bilgilerini içerir. created_by ile users'a bağlı. Her araç bir satıcı tarafından oluşturulur.
❤️ favorites (Composite PK)
(user_id, car_id) bileşik anahtarı. Müşterilerin beğendikleri araçları tutar. Her araç-kullanıcı çifti sadece bir kez.
❓ inquiries
Müşterilerin soruları. handled_by ile admin cevabı. Status: NEW → IN_PROGRESS → CLOSED. İçeriği JSON details'e kaydedilir.
💬 chat_conversations
Araç başına konuşmalar. UNIQUE(user_id, car_id) - Her araç-kullanıcı çifti sadece 1 kez konuşabilir. Real-time mesajlaşma.
✉️ chat_messages
Sohbet mesajları. sender_id ile users'a bağlı. sender_role: USER veya ADMIN. is_read bayrağı okunmuş mesajları işaret eder.
📝 user_activity_logs (YENİ!)
Kullanıcı giriş/çıkış ve aktivite kaydı. Audit trail ve güvenlik takibi amaçlı. action: LOGIN/LOGOUT/FAILED_LOGIN/ACTION. Details JSON formatında ek bilgiler içerir.

⚙️ Sistem Akışı & İş Mantığı

1. Araç Listeleme Akışı

Müşteri Perspektifi:
1. Anasayfaya gir → 2. Mevcut araçları göster (AVAILABLE) →
3. Filtreleme yap (marka, model, fiyat) →
4. Araç detayını aç (resimler, açıklama) →
5. Favoriye ekle veya satıcıyla iletişim kur
Satıcı Perspektifi:
1. Admin paneline giriş yap → 2. Araç ekle (marka, model, fiyat vs.) →
3. Araç resimleri yükle → 4. Araç durumunu ayarla (AVAILABLE) →
5. Müşteri sorularını cevapla → 6. Satış sonrası durumu güncelle (SOLD)

2. Mesajlaşma Mantığı

Chat Flow:
  • Müşteri bir araçla ilgili sorular sorar
  • Sistem chat_conversations kaydı oluşturur
  • Her mesaj chat_messages'te saklanır
  • Mesaj okunmayan olarak işaretlenir (is_read)
  • Admin cevap verir, kullanıcı bildirimi alır
  • Konuşma tamamlanırsa status CLOSED'a çevrilir

3. Favoriler Sistemi

Akış:
  • Müşteri araçı görüp ❤️ ikonuna tıklar
  • favorites tablosuna (user_id, car_id) eklenir
  • Favoriler sayfasında tüm beğenilen araçlar listelenir
  • Favori tekrar tıklanırsa silinir (soft delete)
  • Araç silinirse (is_deleted=1) ilişkili favoriler cascade delete

4. Sorular & Cevaplar

İşlem:
  • Müşteri araç detayında soru sorar
  • Soru inquiries tablosuna kaydedilir (status=NEW)
  • Admin panelde yeni soruları görüp cevaplar
  • Cevap kaydedilir, status IN_PROGRESS → CLOSED olur
  • handled_by ve handled_at alanları doldurulur

  1. Uygulamaya erişir ve araçları görüntüler

  6. Satışı kaydeder ve araç durumunu günceller

Yönetici Özellikleri

📝 Kullanıcı Aktivitesi Kayıt Sistemi

Amaç & Faydaları

Güvenlik Denetimi (Audit Trail): Tüm kullanıcı işlemlerinin kaydını tut
Oturum Yönetimi: Giriş/çıkış zamanlarını ve IP adreslerini takip et
Şüpheli Aktiviteler: Başarısız giriş denemelerini değerlendir
Uyumluluk: GDPR ve diğer veri koruma yönetmeliklerine uyum
Analitik: Kullanıcı davranış analizi ve kullanım istatistikleri

📊 user_activity_logs Tablosu Yapısı

Alan Tanımları:
log_id (PK, BIGSERIAL) - Benzersiz log kaydı
user_id (FK users, NULL) - Giriş yapan kullanıcı (NULL = başarısız giriş)
action (VARCHAR 30) - LOGIN | LOGOUT | FAILED_LOGIN | ACTION
details (JSON) - Ek bilgiler (email, full_name, role, başarısızlık nedeni vb.)
created_at (TIMESTAMP) - Kaydın zamanı (DEFAULT CURRENT_TIMESTAMP)

🔄 İmplementasyon Detayları

AuthController Entegrasyonu:
• Login başarılı → logActivity($userId, 'LOGIN')
• Login başarısız → logActivity(null, 'FAILED_LOGIN')
• Logout → logActivity($userId, 'LOGOUT')
LogRepository Metodları:
• logActivity() - Yeni log kaydı oluştur
• getUserLogs($userId) - Belirli kullanıcının logları
• getLoginAttempts() - Tüm giriş denemelerini listele
• getFailedLoginsByIp() - IP'ye göre başarısız giriş bulma (brute-force tespit)
• deleteOldLogs($days) - Eski logları temizle (GDPR uyumluluk)
• getActivityStats() - İstatistik ve özet bilgiler

💡 Kullanım Örnekleri

// Başarılı giriş
$logRepository->logActivity(1, 'LOGIN', ['email' => 'user@example.com', 'full_name' => 'John Doe', 'role' => 'USER']);

// Başarısız giriş
$logRepository->logActivity(null, 'FAILED_LOGIN', ['email' => 'attacker@mail.com', 'reason' => 'Invalid password']);

// Logout
$logRepository->logActivity(1, 'LOGOUT', ['email' => 'user@example.com', 'full_name' => 'John Doe']);

// Belirli kullanıcının logs (son 50)
$userLogs = $logRepository->getUserLogs(1, 50);

// Başarısız giriş denemelerini listele
$failedAttempts = $logRepository->getFailedLoginAttempts(50);
if (count($failedAttempts) > 5) { /* Suspicious activity */ }

📈 İndeksleme Stratejisi

  • idx_logs_user_id: Belirli kullanıcı loglarını hızlı sorgulamak
  • idx_logs_created_at DESC: Son aktiviteleri hızlı alma
  • idx_logs_action: Action türüne göre filtreleme (LOGIN/LOGOUT/FAILED_LOGIN)
  • idx_logs_user_action_date: Composite index - Kullanıcı+action+tarih sorgularını optimize etme
